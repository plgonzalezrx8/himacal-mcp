# Himacal-MCP v1 Implementation Plan

Historical implementation plan. The project was subsequently verified with the UIDVALIDITY guard, and public GitHub publication with an MIT license was authorized on 2026-11-07. The original no-publishing/no-commits scope below no longer applies to that publication.

> **For agentic workers:** Execute the already-approved plan in the current folder. Use independent, bounded workers for email and calendar adapters, then integrate and review the whole implementation. No additional approval gate is needed for this implementation.

**Goal:** Deliver a Docker-first authenticated HTTP MCP for email and calendars with the approved verification suite.

**Architecture:** One Python service, a pinned Himalaya subprocess adapter, and a Python CalDAV adapter. The root agent owns configuration, HTTP auth/transport, deployment and end-to-end integration.

**Tech Stack:** Python 3.13, mcp 2.3.0, caldav 3.7.0, icalendar 7.3.0, Himalaya 2.2.1, pytest, Docker Compose.

**Spec:** `../specs/2026-11-06-himacal-v1-design.md`

## Global constraints

- Preserve all spec boundaries and exact size/version limits.
- No real account access, remote publishing/deployment, secret mutation or commits requested.
- The workspace started empty; reuse it. There is no existing checkout requiring a worktree.
- Native test/code execution uses Windows tooling; provider acceptance runs in Linux containers.
- Test-audit authoring gate: protect independent behavior, avoid source-string and mirrored-implementation tests.

## Review focus

- A provider accepts a write but response delivery fails: never replay it automatically.
- A mailbox is reset or a calendar is concurrently edited: reject observed stale references.
- An attachment filename contains traversal or an argument resembles an option: never expose host files or execute commands.
- A recurring instance is moved/cancelled: preserve all other components and original recurrence identity.
- An unauthenticated request reaches an alternate method/path or oversized body: reject before provider work.

## Task 1 — Configuration and transport (root)

Files: `src/himacal/config.py`, `errors.py`, `server.py`, `tests/test_config.py`, `tests/test_http.py`.

Interfaces: `Settings.accounts: dict[str, AccountConfig]`, `AccountConfig.email: dict | None`,
`AccountConfig.caldav: CalDAVConfig | None`; CalDAV config URL, username, password_file,
timezone. Settings also supplies public URL, bearer secret and Himalaya binary/timeout.
`ProviderError(code, message).as_dict()` is the safe failure contract.

- [ ] Write configuration and auth behavior tests, run them red, implement strict loading and HTTP guard.
- [ ] Install/lock the approved dependencies; inspect the installed SDK's actual API.
- [ ] Register adapters' typed tools with structured success/error results and proper hints.
- [ ] Verify authenticated current/legacy HTTP, all denied paths and size/host/origin boundaries.

## Task 2 — Email adapter (independent worker)

methods and `register_tools(mcp)`; `close()` cleans up. Raise only safe `ProviderError`s.

- [ ] Add failing behavioral tests for account dispatch, argument boundaries, limits, redaction and unknown outcomes.
- [ ] Implement approved operations against release-specific CLI JSON, private temp files, immutable account selection.
- [ ] Add UIDVALIDITY guards, read-without-seen, reversible trash, safe flags and full forwarding attachments.
- [ ] Run owner tests; return exact method/API receipt for integration.

## Task 3 — Calendar adapter (independent worker)

Files: `src/himacal/calendars.py`, `tests/test_calendars.py`.
Interface: `CalendarService(settings)` exposes typed methods and `register_tools(mcp)`.
Sync provider work must not block HTTP's event loop. Raise safe `ProviderError`s.

- [ ] Add failing tests for dates/DST, reference resolution, conditional writes and recurrence preservation.
- [ ] Adapt script into bounded generic CalDAV operations; merge full resources under ETag conditions.
- [ ] Verify occurrence cancellation/restoration, schedule-write exclusion and safe UID resolution.
- [ ] Run owner tests and return the integration contract.

## Task 4 — Docker and documentation (root)

## Task 5 — Acceptance and review (root)

- [ ] Run one substantive independent whole-implementation review; repair in-scope material findings with regression checks.
- [ ] Run required tests/lint after final fixes, update verification record, report and stop.

## Execution record

- Approved plan recorded before implementation; no prior project conventions or implementation exist.
- Ruling: keep independent adapter workers under the user's explicit delegation policy rather than adding repeated per-task review/approval gates.
- Implemented configuration, typed tools, email/calendar adapters, container targets, configuration examples and setup documentation. The final verification command is `uv run python tests/integration/run.py`; its report is captured in `acceptance-final.log`.
- Independent review completed. Timezone-only patches and incompatible recurring date-type changes now reject before writing; regression cases failed before the fixes and passed afterward.
- Real CLI checks corrected outbound backend selection and IMAP's case-insensitive INBOX identity. The test fixture uses explicit mailbox domains, SASL LOGIN, and SMTP greeting normalization for GreenMail interoperability; production uses the unmodified Himalaya binary.
- User additionally permitted a temporary PurelyMail account if needed; the isolated provider tests made that unnecessary. No live account was accessed.
